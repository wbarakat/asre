## Codebase Patterns
- Package name for snapshot testing is `syrupy`, not `pytest-syrupy`
- All `__init__.py` files are empty placeholders
- CLI entry point: `asre.cli.main:cli` using Click
- mypy configured in strict mode in pyproject.toml
- pytest configured with testpaths = ["tests"] in pyproject.toml
- Test directories (tests/, tests/unit/, tests/integration/) need `__init__.py` files
- Use `from __future__ import annotations` in dataclass modules for `str | None` syntax
- Run tests with `python3 -m pytest` (not `python -m pytest`) on this system
- Use `make test`, `make typecheck`, `make check` for common dev commands
- Shared fixtures in `tests/conftest.py`: sample_canonical_event, sample_encounter, sample_event_batch
- For cross-module Pydantic models on GlobalConfig, use `Any` type (not forward refs) to avoid `model_rebuild()` issues
- Config loader: `load_config(config_path, customer_id)` returns GlobalConfig with `.sources` and `.facility_aliases` attached
- PostgresAdapter takes `config: dict[str, Any]` with keys: host, port, database, user, password, schema
- SQLAlchemy `text()` required for raw SQL strings; `result.mappings()` returns dict rows
- Watermark storage pattern: `asre_metadata` table with key-value columns, `ON CONFLICT` upsert
- IngestQueryBuilder in `asre/ingest/query_builder.py` builds SQL queries per mode (full/incremental) with optional exclude filters
- `resolve_lookback_buffer_hours(lookback_config, source_type)` in query_builder.py parses "24h"/"3d" format strings and falls back to "default" key
- IngestQueryBuilder accepts optional `watermark` (datetime|None) and `lookback_buffer_hours` (int) params for incremental mode
- `dedup_by_source_record_id(records, key_field)` in `asre/ingest/dedup.py` returns `(deduped_records, dedup_count)` tuple
- For mypy strict: use explicit `list[dict[str, Any]]` type annotation when list contains dicts with heterogeneous values (None, missing keys)
- Integration test fixtures: use `Generator[T, None, None]` return type for yield fixtures (mypy strict), use `pytest.skip()` when Postgres unavailable
- Integration test Postgres config: `ASRE_TEST_PG_*` env vars with defaults (host=localhost, port=5432, database=asre_test, user=postgres, password=postgres)
- IngestStage stores raw records on `stage.raw_records` (list of dicts), not in EventBatch.events (those are for CanonicalEvents)
- IngestStage annotates each record with `_raw_payload`, `_source_name`, `_source_type` for downstream canonicalize routing
- Defensive copy before annotation: `dict(record)` before adding metadata keys to avoid mutating adapter-returned dicts
- Migration filenames use `_NNN_description.py` pattern (underscore prefix for valid Python module names); Migrator regex `^_?(\d+)_(.+)\.py$` handles both prefixed and unprefixed
- Migration scripts expose `description: str` and `upgrade(adapter: IngestAdapter) -> None` at module level
- Use `CREATE TABLE IF NOT EXISTS` in migrations for idempotency
- Migrator stores schema_version in asre_metadata table (same table used for watermarks)
- FieldMapper maps raw records to CanonicalEvent; event_type set to "UNKNOWN" (resolved separately by EventTypeResolver)
- CanonicalEvent.facility_raw is required (str, not Optional) — use empty string when mapping not configured
- EventTypeResolver: conditional mappings checked first (order matters), then direct mappings, then "UNKNOWN" fallback
- `_evaluate_condition` handles simple `field == 'value' AND field2 == 'value2'` expressions safely (no eval)
- `_evaluate_flag` handles `event_type IN ('V1', 'V2')` expressions for admit/discharge flag resolution
- PairedEventEmitter in `asre/canonicalize/paired_event_emitter.py` emits two CanonicalEvents from one claims row; uses PairedEvents config for event_ts columns and event_types
- PairedEventEmitter reuses `_parse_event_ts` and `_get_optional` patterns from FieldMapper (static methods, same logic)
- PatientClassResolver in `asre/canonicalize/patient_class_resolver.py` evaluates SQL-like conditions (LIKE, =, IN) safely via regex (no eval)
- `_evaluate_condition` supports: `field LIKE 'pattern%'`, `field = 'value'`, `field IN ('v1', 'v2')` — same safe parsing pattern as EventTypeResolver
- DiagnosisCodeMapper in `asre/canonicalize/diagnosis_mapper.py` handles JSON arrays (strings or objects), native Python lists, and delimited strings (comma, semicolon, pipe)
- DiagnosisCodeMapper.to_serializable() converts `list[DiagnosisCode]` to `list[dict] | None` for CanonicalEvent.diagnosis_codes field
- `record_validator.py` provides `validate_record()` and `process_records_with_tolerance()` — call before FieldMapper/PairedEventEmitter to skip bad records
- CanonicalizeStage receives raw records via `context.config["raw_records"]` and source configs via `context.config["sources"]`
- CanonicalizeStage routes by `_source_name` annotation on records, matching to source config by name
- ADT processing: FieldMapper -> EventTypeResolver; Claims: PairedEventEmitter + PatientClassResolver + DiagnosisCodeMapper; Auth: FieldMapper -> EventTypeResolver -> AuthStatusMapper
- PatientClassResolver conditions use `when` and `patient_class` keys (not `condition` and `value`)
- EventTypeResolver conditional_mappings use `when` key (not `condition`)
- FacilityNormalizer pipeline: uppercase -> strip punctuation -> expand abbreviations -> remove generic suffixes -> normalize whitespace
- "ST" is NOT expanded to "SAINT" in facility names (PRD expects "ST MARYS" not "SAINT MARYS")
- Generic suffix removal strips preserved directional/campus tokens first, removes suffix from core, then re-appends preserved tokens
- Default abbreviations do NOT include "ST"->"SAINT" — abbreviation list is in `asre/facility/normalizer.py`
